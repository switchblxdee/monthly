# Голос IT — прототип мультиагентной системы

Краткая последовательность установки и проверки во внутреннем контуре: [ПЕРВЫЙ_ЗАПУСК.md](ПЕРВЫЙ_ЗАПУСК.md).

При `--gigachat` основной граф LangGraph передаёт работу четырём агентам: `data` читает и подготавливает книгу, `analyst` сопоставляет темы и рассчитывает показатели, `editor` готовит цитаты и сводку, `presentation` собирает, проверяет и сохраняет PPTX. Каждый агент — отдельный LangGraph-подграф с циклом «модель → инструменты → модель» и собственным набором инструментов, выполняющих реальные операции. Агенты получают состояние от предыдущего участника, могут осмотреть данные и принять решение о доступных повторах. По умолчанию исходные данные остаются локальными. При флаге --gigachat передаются названия тем, продуктов и агрегаты; флаг --gigachat-quotes дополнительно передаёт маскированный текст кандидатов. Используйте только внутренний адрес, разрешённый для этих данных.

Инструменты работают с переданным состоянием и заданными путями; порядок обязательных действий и проверка PPTX перед сохранением обеспечиваются программно. Агенты могут просматривать сводные данные и темы; обращений через инструмент просмотра они не получают. Отбор цитат отправляет маскированные тексты модели только с `--gigachat-quotes`. Агент аналитики может повторить сопоставление с `--gigachat-match`, агент-редактор — выбор цитат с `--gigachat-quotes`; каждый повтор доступен один раз. На каждого агента выделено до 24 ответов модели. Выполненные инструменты и число ответов сохраняются в `agent_decisions` файла аудита. Если агент не завершил обязательную работу или модель не поддерживает `bind_tools`, агентный запуск останавливается. Без `--gigachat` доступен локальный детерминированный конвейер без вызовов модели.

## Запуск

Нужны Python 3.10+ и зависимости. Для сборки по исходному шаблону (`--template`) LibreOffice не требуется. Для упрощённого выпуска без шаблона нужен LibreOffice (`soffice` в PATH):

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
golos-it вход.xlsx --current-sheet 'приоритет октябрь' --previous-sheet 'приоритет сентябрь' --period 'октябрь 2026' --report-month 2026-10 --template 'образец.pptx' --output выпуск.pptx
```

Для сводки с GigaChat настройте во внутреннем контуре `GIGACHAT_BASE_URL`, `GIGACHAT_CREDENTIALS`, `GIGACHAT_SCOPE` и доверенный сертификат, после чего добавьте `--gigachat`. Для отбора цитат моделью добавьте оба флага: `--gigachat --gigachat-quotes`. Для каждой темы высокого приоритета или UX уникальные пары «источник — нормализованный текст» обрабатываются пакетами до 12: на каждый запрос передаются название источника и первые 800 символов обращения. Затем выбранные записи при необходимости повторно сокращаются до трёх. Модель возвращает номера, а оригиналы текстов и координаты берутся только из Excel. При ошибке частичный выбор отбрасывается, используется отбор по лайкам и появляется предупреждение. Без флага --gigachat запросы к модели не выполняются. Документация: https://developers.sber.ru/docs/ru/gigachain/tools/python/langchain-gigachat

При использовании `GIGACHAT_CREDENTIALS` также обязательно явно укажите `GIGACHAT_AUTH_URL`: адрес сервера авторизации задаётся отдельно от `GIGACHAT_BASE_URL`. Получите оба адреса и способ авторизации у администратора внутреннего контура. Проверка наличия адресов не определяет, являются ли они внутренними, и не подтверждает сетевую маршрутизацию. При авторизации предварительно полученным токеном настройка зависит от внутреннего сервиса.

Перед первым запросом программа проверяет, что экземпляр обёртки GigaChat раскрывает заданные `base_url` и, если он указан, `auth_url` с теми же значениями. Если установленная версия не подтверждает их, запуск останавливается до обращения к модели. Это проверка параметров обёртки, а не проверка DNS, прокси, маршрутизации или внутреннего расположения сервиса; реальную версию SDK и контур необходимо проверить на месте.

Рядом с презентацией появится `.audit.json`: он содержит номера строк, выбранные цитаты и предупреждения. Файл аудита содержит тексты обращений, храните его с теми же ограничениями, что Excel. Excel считывается с `data_only=True`: для формул нужны сохранённые в книге вычисленные значения.

Отсутствующие сохранённые результаты формул отмечаются в предупреждениях для расчётных полей приоритетов и для даты, лайков и сигнала в строках детализации. При выборе месяца проверяются строки этого месяца и строки с нераспознанной датой; строки с известной датой другого месяца не добавляют предупреждений о формулах. Пустая ячейка без формулы не обозначается как формула без результата. Проверка не пересчитывает Excel.

Чтобы убедиться, что файлы относятся к одному запуску, выполните `golos-it-verify отчёт.pptx` или `python -m golos_mas.verify отчёт.pptx`. Команда сравнит SHA-256 презентации со значением, сохранённым в аудите; иной путь к аудиту можно указать через `--audit`. Сбой при сохранении аудита может оставить новую презентацию рядом со старым аудитом — проверка обнаружит такое несовпадение. После ручного редактирования презентации контрольная сумма также изменится. Это проверка соответствия файлов, а не доказательство подлинности или корректности данных.

## Текущие ограничения

При сборке по шаблону встроенные OLE-объекты исходных слайдов удаляются. Проверка готового файла отклоняет встроенные объекты, ActiveX, макросы, заметки, комментарии и пользовательские XML-части. Это не заменяет визуальную и содержательную проверку презентации перед использованием.

Это рабочий прототип. При указании --template используются обложка, Summary, методика, разделители, таблицы, легенда и макет цитат исходного файла. Шаблон должен соответствовать показанному образцу. Без шаблона используется упрощённый макет. Оглавление подразделений собирается на одном слайде; при большом объёме проверьте читаемость плашек. Полная адаптация длинного текста ещё требует проверки. Блок мониторинга обещаний включается только при наличии отдельного подготовленного снимка, описанного ниже. UX-темы выносятся в отдельные сводные таблицы без столбца зоны. Детальные страницы создаются только для тем высокого внимания; UX остаётся в сводной таблице. Исходные источники обещаний и статусов не предоставлены; поддерживаются дополнительные форматы, описанные ниже. Итоговый балл берётся из Excel. Если он отсутствует, но все три балла критериев корректны, система вычисляет сумму и отмечает это в аудите. Расхождение суммы с готовым баллом также отмечается. Два месяца истории позволяют установить наличие темы в предыдущем месяце, но не длительность более двух месяцев. Темы сопоставляются по продукту и тексту; незначительные различия могут быть сопоставлены автоматически при высокой уверенности, с предупреждением в аудите. Более сложные перефразировки требуют проверки. Если несколько тем претендуют на одни и те же обращения, система не прикрепляет их автоматически и пишет предупреждение. Значок определяется по Excel: длительность 1 и пустой комментарий — новая тема; 1 и «возобновилось» — возобновление; 2 — два месяца; 3 и более — три месяца и более. Без длительности или при непонятном комментарии для 1 значок не угадывается. Если отдельный файл статусов противоречит этому правилу, приоритет у Excel и формируется предупреждение. Значки контроля и митигации назначаются только по дополнительному источнику статусов, описанному ниже. При отсутствии записей по теме цитаты не подставляются. Сводка модели и итоговая презентация требуют проверки. Темы высокого внимания одного продукта объединяются на детальных страницах по доступному месту; длинные цитаты сокращаются с многоточием, оригиналы сохраняются в аудите.

Флаг `--report-month YYYY-MM` ограничивает строки детализации по дате; нераспознанные даты исключаются с предупреждением. Если текущий лист и месяц не заданы, система определяет последний отчётный месяц по листам «приоритет месяц» и датам детализации либо по году в названии листа. При отсутствии надёжной информации о годе запуск требует `--report-month`; выбор автоматически найденного месяца отмечается в предупреждениях. Если пользователь явно указал лист и период без `--report-month`, используется вся детализация с предупреждением при нескольких месяцах.

При фильтрации в разделе `date_filter` локального аудита сохраняются количество принятых строк и координаты исключённых строк: отдельно для других месяцев и для нераспознанных дат. Строки без продукта или темы отбрасываются до фильтрации; их полный список с номерами листов, строк и отсутствующих полей сохраняется в `skipped_rows`, а в предупреждении показаны первые примеры. Этот список может включать строки любого месяца.

Если в обнаруженной пропущенной строке продукт или тема заданы формулой без сохранённого результата, соответствующее поле будет перечислено в `uncached_key_formulas` и в предупреждении. Текст формулы в этот список не копируется.

В разделе `coverage` показатель `selected_quote_rows` учитывает выбранные обращения по всем темам, а `presentation_quote_rows` и `presentation_quote_references` — только действительно показанные обращения тем высокого внимания.

Параметр `--max-quotes-per-topic` ограничивает число отобранных цитат в аудите (по умолчанию 3); на слайдах показываются до двух выдержек на тему. Полные тексты выбранных цитат и координаты сохраняются в аудите. Это отдельная настройка от `--gigachat-max-candidates`, который ограничивает объём данных, передаваемых модели для выбора.

Модель просят возвращать выбранные обращения в порядке соответствия теме. Если при ограничении до одной или двух цитат финальные кандидаты получены из разных пакетов, они дополнительно сравниваются одним запросом. Порядок и релевантность всё равно требуют проверки человеком.

После сборки QualityAgent проверяет целостность PPTX, число слайдов и связи внутри слайдов. Для длинных тем и названий он добавляет предупреждения в аудит. Автоматическая проверка связей не заменяет визуальный просмотр.

## Дополнительные статусы

Скриншоты книги не содержали определённого источника статусов и сроков. Поэтому генератор не пытается их угадывать. При наличии проверенных данных можно указать `--statuses-json статусы.json`. Формат показан в `statuses.example.json`. Это дополнительный формат проекта, а не утверждение о структуре вашей книги.

`product` и `topic` обязательны и точно сопоставляются с текущим листом приоритетов без учёта регистра и лишних пробелов. Остальные поля необязательны:

- `recurrence` — дополнительное поле в файле статусов: `new`, `two`, `long`, `resumed`. При расхождении с длительностью и комментарием Excel сохраняется предупреждение; значок определяется данными Excel. Отсутствие темы за прошлый месяц само по себе не означает, что тема новая.
- `controls` — список: `aibolit` (АйболИТ+), `promise_monitor` (мониторинг обещаний), `pain_candidate` (кандидат на боль), `backlog` (бэклог команды).
- `mitigation` — одно значение: `done` (выполнено), `analysis` (на анализе), `release` (релиз), `limitations` (текущие ограничения).
- `version`, `deadline` — текстовые значения версии и срока.
- `promnenie`, `after_close` — логические значения для ПроМнения и повтора после закрытия.

Повторяющиеся записи и неизвестные значения останавливают запуск. Неоднозначные и несопоставленные записи отмечаются в аудите; статусы к ним не применяются. Файл статусов сам по себе не является реестром обещаний и не заполняет отдельный раздел их мониторинга.

## Дополнительный снимок обещаний

Показанная книга не содержит известного реестра обещаний. Если такой источник будет доступен, можно подготовить отдельный снимок в формате `promises.example.json` и передать `--promises-json обещания.json --report-month 2026-10 --template образец.pptx`. Это предложенный формат проекта, а не описание существующей у вас таблицы.

Каждая запись требует уникальные строки `id`, `owner`, `description`, `source`; срок `initial_due` в ISO-формате `YYYY-MM-DD`; статус `outcome`; логические поля `in_work_start` и `in_work_current`. `initial_due` — срок, действовавший на начало **отчётного** месяца, либо назначенный для нового обещания в этом месяце; он используется для определения обещаний со сроком в месяце. `in_work_start` и `in_work_current` — явные признаки на начало и конец периода. В снимок следует включать все обещания, необходимые для итогов, в том числе выполненные в отчётном месяце; данные, отсутствующие в снимке, не учитываются.

`outcome`: `completed_on_time` (в срок), `completed_early` (досрочно), `postponed` (перенос), `status_missing` (статус не предоставлен), `in_progress` (в работе). Для переноса обязателен `current_due` позже `initial_due`. `comment` необязателен. Генератор не выводит причин переноса из текста и не определяет статусы самостоятельно.

Доля выполнения: число выполненных в срок и досрочно, делённое на число записей со сроком в отчётном месяце. Если знаменатель равен нулю, отображается прочерк. После сводки и таблицы по ответственным выводятся записи с явным статусом `postponed`; комментарии и источники берутся из снимка. Эта реализация требует проверки бизнес-правил на вашем фактическом реестре.

## Диагностика книги и сопоставление тем

В аудите `coverage` показывает число тем приоритетов с найденными строками, количество сопоставленных и несопоставленных строк детализации, а также координаты несопоставленных строк. Эти числа относятся только к прочитанным листам и периоду, а не ко всей обратной связи организации. В предупреждения попадают отсутствующие столбцы и строки, в которых не заполнены продукт или тема. По умолчанию читаются листы SH, SI, SD, SU, SW и «прочее»; чтобы выбрать другие, повторите параметр `--detail-sheet`, например `--detail-sheet SW --detail-sheet 'Новый лист'`.

Для случаев, когда обобщённый продукт или название темы отличаются от записей детализации, можно передать подготовленную карту `--topic-map-json карта.json`. Формат описан в `topic-map.example.json`. Одной теме приоритетов можно сопоставить несколько пар продукт/тема детализации отдельными записями. Если пара детализации указана для двух разных тем приоритетов, запуск останавливается. Карта переопределяет автоматический поиск для указанной темы; отсутствующие пары отмечаются в аудите. Карту нужно составить по проверенным данным: система не утверждает, что примеры в файле соответствуют вашей книге.

## Сопоставление тем через GigaChat

При `--gigachat --gigachat-match` отдельный агент пробует найти соответствия для тем, которые не сопоставились точно или по строгому сравнению написания и для которых нет явной карты. Он подбирает до 25 кандидатов по общим словам и продукту, передаёт модели только формулировки продуктов и тем и принимает в ответ номера существующих кандидатов. Тексты обращений для этого режима не передаются. Отсутствие общих слов, ограничение числа кандидатов и ошибки модели могут оставить подходящие записи несопоставленными.

При отборе цитат по лайкам некорректное значение лайков считается нулём; координата строки добавляется в предупреждения аудита. Пустое значение также считается нулём.

Для выбранных цитат аудит сохраняет исходные поля `likes`, `signal` и значение `likes_for_ordering`, использованное для первоначальной сортировки. При выборе GigaChat эта сортировка определяет порядок кандидатов, но итоговую последовательность предлагает модель. В запрос отбора по-прежнему передаются только номер, источник и фрагмент текста кандидата.

Точные и заранее заданные соответствия имеют приоритет. Если две темы претендуют на одни и те же записи, автоматическая подстановка отменяется. Сопоставления модели отражены в `match_method` как `gigachat` и сопровождаются предупреждением: перед выпуском их нужно проверить. Режим `--gigachat-match` не включает `--gigachat-quotes`: передача маскированных текстов для отбора цитат по-прежнему включается отдельно.

Шаблонизатор ожидает конкретную структуру предоставленного образца и проверяет ключевые заголовки на фиксированных слайдах. Для другой версии шаблона его нужно адаптировать; произвольный PPTX не поддерживается.

Цвет продукта в оглавлении определяется по наиболее высокой из известных зон его тем: высокое внимание, потенциальный риск, наблюдение. Если известны только UX-темы или зона не определена, используется отдельная фиолетовая отметка. Это правило генератора требует подтверждения на ваших рабочих данных.

Презентация сначала создаётся во временном файле в целевой папке. После успешной проверки структуры готовый файл заменяется атомарно; при ошибке проверки прежняя презентация сохраняется. Файл аудита также записывается через временный файл, но презентация и аудит заменяются отдельно. Для запуска тестов дополнительно установите `pytest`; тесты шаблона запускаются с `GOLOS_TEST_TEMPLATE=/путь/к/образцу.pptx`.

Summary и `coverage` считают сумму сигналов по прочитанным строкам детализации, а не общий объём обратной связи организации. Суммируются только неотрицательные целые числовые значения; число строк, вошедших в сумму, указывается отдельно. Источники считаются по непустым названиям. Записи с одинаковыми датой, источником и нормализованным текстом отмечаются как возможные повторы, но не удаляются: совпадающий текст может встретиться у разных сообщений. При отсутствии даты, текста или источника автоматическая проверка повтора невозможна.

## Проверка подключения GigaChat

После установки зависимостей и настройки `GIGACHAT_BASE_URL` можно выполнить `golos-it-check-gigachat`. Команда проверяет наличие пакетов, указанного адреса и, если задан `GIGACHAT_CA_BUNDLE_FILE`, файла сертификата. По умолчанию она не обращается к сети.

Для реальной проверки внутреннего сервиса используйте `golos-it-check-gigachat --ping`. Будет отправлено только фиксированное тестовое сообщение «Ответь одним словом: ОК», без книги и обращений; успешный непустой ответ подтвердит доступность вызова. Результат модели и текст исключения не выводятся, чтобы не раскрыть возможные служебные данные. Для работы нужен доступ к внутреннему контуру и его способ авторизации. В этом проекте диапазон интеграции ограничен `langchain-gigachat>=0.5,<0.6`, а LangGraph — `>=1,<2`; сверка публичного интерфейса выполнена по официальной документации, реальный запрос из среды разработки не проводился.

## Проверка на вымышленном наборе

Команда ниже создаёт новую папку с полностью вымышленной книгой, картой тем, статусами, снимком обещаний и ожидаемыми итогами. Она не перезаписывает существующую папку.

```bash
golos-it-create-demo --output-dir ./учебный-набор
golos-it ./учебный-набор/demo.xlsx \
  --current-sheet 'приоритет ноябрь' \
  --previous-sheet 'приоритет октябрь' \
  --period 'ноябрь 2026' --report-month 2026-11 \
  --template 'путь/к/исходному-образцу.pptx' \
  --topic-map-json ./учебный-набор/topic-map.json \
  --statuses-json ./учебный-набор/statuses.json \
  --promises-json ./учебный-набор/promises.json \
  --output ./учебный-набор/результат.pptx
```

Ожидается четыре темы приоритетов, пять строк детализации после фильтрации, сумма 206 сигналов и два обещания со сроком в месяце, из которых одно выполнено, одно перенесено. Те же значения находятся в `expected.json`. GigaChat для этой проверки не требуется. Исходный PPTX-образец в состав проекта не включён: путь к нему передаётся отдельно.

На детальных страницах высокого приоритета значки повторяемости, контроля, митигации, ПроМнения и повтора после закрытия копируются из легенды исходного шаблона и получают текстовые описания. Если для явно указанного статуса значок в шаблоне отсутствует, сборка останавливается с ошибкой.

Чтобы отдельно извлечь 14 значков легенды и шесть значков методики с каталогом их назначения, выполните `golos-it-extract-icons 'образец.pptx' --output-dir ./значки` или `python -m golos_mas.icons 'образец.pptx' --output-dir ./значки`. Папка должна быть новой; откройте её `index.html`, чтобы просмотреть значки с подписями. Извлекаются изображения со слайдов 4 и 6, а не все изображения и логотипы презентации; генератор по-прежнему использует указанный PPTX как шаблон.

## Локальная проверка структуры вашей книги

Для диагностики без передачи книги можно локально выполнить:

```bash
golos-it-inspect-workbook 'путь/к/книге.xlsx' --output schema.json
```

Команда работает локально, не вызывает GigaChat и не меняет книгу. Она показывает листы только как `Sheet_1`, `Sheet_2` и т. д. в порядке вкладок, распознанные поля, счётчики строк и число формул без сохранённого результата. Исходные названия листов, заголовки, имена продуктов, тексты обращений, сами формулы и значения ячеек не выводятся. Нераспознанный лист не означает, что он пустой: возможно, его заголовки отличаются от ожидаемых.

Счётчик `rows_with_no_keys_but_other_values` показывает строки с заполненными распознанными полями, но без продукта и темы; генератор не сможет их сопоставить. Строки с одним из двух ключей отражены в `rows_with_only_one_key`. Формулы без сохранённого результата учитываются отдельно, поэтому эти показатели не заменяют проверку книги.

`rows_with_no_keys_and_uncached_formula` показывает число строк без прочитанных продукта и темы, где хотя бы одна распознанная формула не имеет сохранённого результата. Этот счётчик может пересекаться с предыдущим и позволяет обнаружить строки, которые при чтении сохранённых значений выглядят пустыми.

Отчёт всё же содержит **агрегированные показатели и структуру книги**. Прежде чем кому-либо передавать его, проверьте, допускает ли это ваша политика NDA. По умолчанию проверяется не более 100 000 строк каждого распознанного листа; при ограничении поле `truncated` будет истинным. Лимит можно изменить параметром `--max-rows`. Формулы не пересчитываются: `missing_cached_value` показывает формулы, у которых нет сохранённого результата для чтения генератором.

## Автоматический выбор месяца

Если листы названы, например, `приоритет ноябрь` и `приоритет октябрь`, достаточно указать месяц:

```bash
golos-it вход.xlsx --report-month 2026-11 --template образец.pptx --output выпуск.pptx
```

Генератор найдёт лист приоритетов за ноябрь и, если он есть, за октябрь; название периода для слайдов тоже сформирует автоматически. При переходе с января на декабрь учитывается смена года. Поддерживаются русские названия месяцев в именительном и родительном падежах, с необязательным годом, например `приоритет ноября 2026`. Если совпадающих листов несколько, запуск остановится и попросит указать `--current-sheet` или `--previous-sheet`. Лист с подходящим явно указанным годом имеет приоритет перед листом без года. Если выбранный автоматически лист не содержит год, в аудит добавляется предупреждение: проверьте, что это нужный период.

Явные `--current-sheet`, `--previous-sheet` и `--period` по-прежнему поддерживаются. Параметр `--no-previous` отключает поиск предыдущего листа: в таком случае отсутствие истории не считается признаком новой темы. Названия выбранных листов фиксируются в локальном аудите `source_sheets`.

## Проверка балла по методике

`PrioritizationAgent` сверяет балл за количество сигналов в листе приоритетов с порогами для малого, среднего и большого продукта на слайде 4. При действительно отсутствующем MAU применяется средняя аудитория, как указано в образце; при менее чем 10 сигналах методика балла не задаёт. Если вместо отсутствующего значения находится формула MAU без сохранённого результата, средняя аудитория не подставляется и автоматический расчёт не выполняется. Проверка и её основание записываются в `methodology_check` локального аудита. Расхождение выводится в предупреждения, но исходные значения и итоговая зона не переписываются.

Подтверждённое правило по умолчанию: MAU 1 000 относится к средним продуктам, а 20 000 — к большим (`--mau-boundaries upper`). Для проверки исторических выпусков можно явно выбрать `lower` (граница относится к предыдущей категории) или `ambiguous` (не определять балл на границе). Применённое правило сохраняется в аудите.

## Нестандартные столбцы

Если заголовки или их расположение отличаются от показанных на скриншотах, можно подготовить локальный файл по примеру `schema.example.json` и передать `--schema-json схема.json` как генератору, так и команде `golos-it-inspect-workbook`. Пример содержит вымышленные названия листов: замените их точными названиями из своей книги. `header_row` — номер строки заголовка, считая с единицы; значения в `columns` — буквы столбцов Excel. Поля, не перечисленные явно, определяются по известным заголовкам в этой строке.

Идентификаторы для приоритетов: `owner`, `product`, `topic`, `mau`, `count`, `signals_score`, `duration`, `impact`, `score`. Для детализации: `date`, `source`, `product`, `topic`, `text`, `likes`, `signal`, `support`. `product` и `topic` должны указывать разные столбцы. Один явно заданный столбец нельзя назначить двум полям. Нестандартные имена листов детализации дополнительно задаются через повторяемый `--detail-sheet`.

При повторяющихся распознанных заголовках генератор не выбирает один наугад: нужно явно сопоставить соответствующие поля. Команда проверки структуры покажет их в `duplicate_recognized_fields`, не раскрывая исходные заголовки. Ошибочные ссылки на столбцы и отсутствующие листы останавливают сборку.

Если балл за сигналы пуст или его формула не имеет сохранённого результата, а MAU и количество сигналов позволяют однозначный расчёт по методике, система вычисляет этот балл. При наличии остальных двух корректных критериев она также может вычислить отсутствующий итоговый балл. Поля `signals_score_input`, `signals_score_origin`, `score_origin` и `uncached_formulas` сохраняют происхождение значений в локальном аудите. Заполненный некорректный балл автоматически не заменяется; UX-метка не преобразуется в числовую оценку. Книга не изменяется.

## Сводка с GigaChat и происхождение чисел

В таблицу Summary попадают три темы высокого внимания с наибольшим числом сигналов; при равенстве используется балл. При `--gigachat` модель выбирает для текстовой сводки только из этих трёх тем. Она возвращает только номера. Произвольный текст модели в презентацию не вставляется: формулировки и текущие значения берутся из листа приоритетов. Длинные названия на слайде сокращаются с многоточием, полные доступны в аудите и детализации. В `narrative_sources` сохраняются координаты использованных строк. Выбор тем может быть нерепрезентативным и требует проверки.

Изменение к прошлому листу считается локально, только если владелец, продукт и тема совпадают однозначно и значения сигналов целые, неотрицательные, а прошлое значение больше нуля. Процент относится к конкретной теме в листах приоритетов, а не ко всему потоку обратной связи. Система не делает выводов о причинах роста или падения по одному числовому сравнению. Если модель недоступна или вернула некорректные номера, её выбор не используется и в аудит добавляется предупреждение.

На одной детальной странице могут помещаться несколько тем высокого внимания одного продукта и до двух выдержек по каждой теме. Из выдержек удаляются распознаваемые служебные маркеры, идентификаторы, время и описания изображений без перефразирования слов клиента; если достоверную выдержку извлечь не удалось, выдаётся предупреждение. Длинная выдержка обозначается многоточием; полный текст выбранных обращений и координаты строк остаются в аудите. На последней странице продукта по одному виджету перечислены источники всех сопоставленных тем продукта. Виджет M-App использует ссылку из шаблона только для адреса mapp.sberbank.ru. Показатели и дельты CSAT и ПроМнения читаются из приоритетного листа и показываются на последнем слайде продукта. Если в строках продукта указаны разные числовые значения, на слайде показывается наблюдаемый диапазон. Прочерк означает отсутствие читаемых значений. Происхождение и список наблюдаемых значений сохраняются в `product_metrics` аудита. Названия источников выводятся в плашках высотой 7 мм в одну строку. Если они не помещаются, список продолжается на дополнительных слайдах продукта. Полный список с координатами доступен в `product_sources` аудита.

В сводных таблицах продукты сортируются по сумме сигналов тем, при равенстве — по числу тем высокого внимания. Внутри продукта сохраняется порядок исходных строк для одинаковой зоны, а зоны идут от высокого внимания к потенциальному риску и наблюдению. Соседние ячейки с названием продукта объединяются в пределах текущего слайда; на новой странице название повторяется. UX остаётся отдельным блоком.

При `--gigachat-quotes` по умолчанию нет ограничения числа уникальных кандидатов; для больших книг это может потребовать много запросов и времени во внутреннем сервисе. `--gigachat-max-candidates 120` ограничит число кандидатов на тему до 120, начиная с наибольшего числа лайков. Ограничение и фактические попытки фиксируются в `quote_selection_stats`; оставшиеся кандидаты не были обработаны моделью. При ошибке даже частичный выбор модели не используется.

Перед включением GigaChat можно сделать локальный запуск без него: `quote_candidate_count` и `quote_model_max_calls_unlimited` в аудите показывают размер набора и верхнюю оценку числа запросов для каждого набора при неограниченном выборе за один проход. В `coverage` есть суммарная оценка для тем высокого внимания и UX. При повторе прохода вызовов может быть до двух раз больше этой оценки; вызовы агентов и остальные вызовы модели учитываются отдельно. Это оценка количества вызовов, не времени или стоимости. Аудит содержит выбранные цитаты и ссылки на все сопоставленные строки, но не копирует целиком все необранные обращения из книги.

В упрощённом режиме без `--template` темы высокого внимания одного продукта также группируются на страницах, с двумя короткими выдержками на тему. Макет остаётся упрощённым, полные темы и выбранные обращения сохраняются в аудите. Для данных из `--statuses-json` и для раздела обещаний исходный `--template` обязателен: упрощённый режим не должен незаметно терять значки или раздел.

Агентам доступны `inspect_sheets`, `inspect_sources` и `inspect_topic_sources`: они показывают число учтённых строк, источники с разбивкой по листам и координаты сопоставленных строк. `source_inventory` сохраняется в состоянии и в аудите; результаты просмотра разбиваются на страницы по 50, без ограничения исходных данных. Учёт строк детализации относится к выбранному периоду и строкам с распознанными обязательными полями. `source_references` у каждой темы связывает названия источников с листами и строками.
